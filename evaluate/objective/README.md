# M2VBench objective evaluation

Code for the five objective metric families in Section 3.3 and Table 2 of
**AutoMV: Lyric-Grounded Multi-Agent Planning for Full-Song Music Video Generation**.
The existing [LLM rubric evaluator](../LLM/llm_judge.py) is a separate evaluation component.

| Metric | Implementation | Paper protocol |
| --- | --- | --- |
| ImageBind (IB), higher is better | [imagebind_score.py](imagebind_score.py); original [IB evaluator](../IB/inference_batch.py) | Cosine between song-audio and video embeddings, using ImageBind's default transforms. The new wrapper matches `4.wav` with either `4.mp4` or `mv_4.mp4`. |
| CLAP, higher is better | [clap_score.py](clap_score.py), [caption.py](caption.py), [run.py](run.py) | `laion/clap-htsat-unfused`; song audio versus an MLLM-generated video caption. First 60 s of audio at 48 kHz, in 10 s windows; normalize each window, mean-pool, normalize again. |
| FVD, lower is better | [fvd_score.py](fvd_score.py) | `cd-fvd==0.1.1`, I3D Kinetics-400; four uniformly spaced 16-frame clips per video, stride `round(fps/16)`, stretched to 224 × 224; official MVs are the reference distribution. |
| Beat, higher is better | [beat.py](beat.py), [run.py](run.py) | Gaussian beat pulses (sigma 0.10 s) versus Farneback optical-flow magnitude on an 8 Hz grid; maximum normalized cross-correlation over ±6 samples, averaged over valid lyric-aligned segments. |
| LSE-D / LSE-C, lower / higher is better | [lipsync_score.py](lipsync_score.py) | Adapter to official SyncNet face tracking and distance/confidence estimation, for selected singing footage. |

The Beat implementation preserves the research code's normalization over the
whole segment before slicing at each lag. It is distinct from nearest-beat BAS
and shot-cut alignment. FVD is a distribution-level score, not a per-song score.

## Rebuild the archived table without models

From the repository root, with Python 3.9 or newer:

```bash
python3 evaluate/objective/summarize.py
```

This verifies SHA-256 checksums of the imported inputs and reconstructs:

- [summary.csv](results/summary.csv): method means, sample standard deviations,
  valid counts, and FVD; IB/CLAP/Beat are multiplied by 100, as in the paper.
- [per_song_scores.csv](results/per_song_scores.csv): 150 rows for 30 shared songs
  and five methods. Music2Video song 38 has no archived CLAP score, so its CLAP
  mean uses 29 songs; the missing value stays empty.
- [paper_table2.csv](results/paper_table2.csv): the displayed manuscript values,
  transcribed from Table 2, including LSE. Empty cells mean unavailable or not
  applicable; the human FVD entry is the reference.

**LSE provenance:** the local research checkout contains the other four metric
families' scores, but the original LSE scripts, selected singing/face tracks,
and per-video records were not found. The LSE columns above are manuscript
values, not results regenerated by this release. The new SyncNet adapter makes
the metric runnable on new footage; recovering the exact historical numbers
also requires the original singing selection and aggregation protocol.

MV-Crafter and CHARCHA use different songs and shorter demo videos. FVD and Beat
are compared only on the shared 30-song set. The original AutoMV `mv_16.mp4`
stream truncates near 10.7 s even though its container reports a longer duration;
archived scores are retained and the affected per-song row is flagged.

## Input layout and dependencies

Use Python 3.10 or 3.11 for model inference. A typical layout is:

```text
/data/
  audio/4.wav, 6.wav, ...
  GroundTruth/mv_4.mp4, mv_6.mp4, ...
  AutoMV/mv_4.mp4, mv_6.mp4, ...
  OpenArt/4.mp4, 6.mp4, ...
  segments/4.json, 6.json, ...
```

The shared song IDs are defined in [common.py](common.py). The bundled
[segments/](segments/) directory contains lyric timing boundaries for those
30 songs. Each file is `{"segments":[{"start":0.0,"end":4.2}, ...]}` in seconds;
lyric text is unnecessary for these metrics. Supply `--segments-dir` for another
song set, and `--ids 4 6` to evaluate an explicit subset. Duplicate IDs and
missing requested inputs are errors.

Install FFmpeg and the Beat/CLAP dependencies in a dedicated environment:

```bash
conda create -n automv-metrics python=3.11 ffmpeg -c conda-forge
conda activate automv-metrics
pip install -r evaluate/objective/requirements.txt
```

Model weights download on first use. `HF_ENDPOINT` can optionally select a
Hugging Face mirror. Beat needs NumPy, OpenCV, librosa and FFmpeg; it neither
loads CLAP nor requires an API key. The archive summary uses only the Python
standard library.

## Beat and CLAP on a new batch

Beat can run on its own:

```bash
python evaluate/objective/run.py \
  --dir /data/AutoMV --name AutoMV --metrics beat \
  --output-dir evaluate/objective/outputs/AutoMV
```

For CLAP, first provide a JSONL file with `id` and `caption`, or generate captions:

```bash
export GEMINI_API_KEY="YOUR_GEMINI_API_KEY"
python evaluate/objective/caption.py \
  --dir /data/AutoMV --out evaluate/objective/outputs/tags_AutoMV.jsonl
python evaluate/objective/run.py \
  --dir /data/AutoMV --name AutoMV --metrics beat clap \
  --captions evaluate/objective/outputs/tags_AutoMV.jsonl \
  --device cuda:0 --output-dir evaluate/objective/outputs/AutoMV
```

The caption generator preserves the archived Gemini-3.1-Pro prompt and
temperature 0; its prompt includes the video's visuals **and audio**. This is a
caption-assisted metric, so generating captions involves an MLLM API call.
`--model` can select another available model; record that change when reporting
scores. The caption model is separate from the Gemini-3.5-Flash rubric judge.
Archived captions in `results/raw/tags_*.jsonl` belong to the original videos;
generate new captions for new videos.

The batch runner writes `beat_<name>.jsonl` and `clap_<name>.jsonl`, with raw
unscaled scores and song IDs. It resumes existing rows independently per metric;
use a fresh output directory when changing inputs or protocol. Failures are
recorded in `errors_<name>.jsonl` and cause a nonzero exit status.

## ImageBind

Use a separate Linux environment for ImageBind and its video dependencies:

```bash
pip install -r evaluate/objective/requirements-imagebind.txt
python evaluate/objective/imagebind_score.py \
  --audio-dir /data/audio --video-dir /data/AutoMV \
  --device cuda:0 --output-dir evaluate/objective/outputs/IB_AutoMV
```

`metrics.json` contains paired cosine scores, their mean, the valid count and
explicit errors. Pairing uses song IDs; unmatched files do not become retrieval
scores. The original `evaluate/IB/inference_batch.py` also supports retrieval
evaluation, while the paper uses paired similarity.

## FVD

Install [requirements-fvd.txt](requirements-fvd.txt) in a separate Linux
environment with CUDA. The upstream package downloads its I3D checkpoint.

```bash
pip install -r evaluate/objective/requirements-fvd.txt
python evaluate/objective/fvd_score.py \
  --reference-dir /data/GroundTruth \
  --generated AutoMV=/data/AutoMV OpenArt=/data/OpenArt \
  --device cuda --out evaluate/objective/outputs/fvd.json
```

Every group must contain exactly the requested reference song IDs. The output
records clip counts, frame rates, readers and decoding failures. The archived
protocol uses decord with an OpenCV fallback; `--fallback AutoMV=/data/AutoMV_fixed`
can supply re-encoded files when the original stream is damaged. With only
30 songs, FVD should be interpreted together with the other metrics.

## Lip synchronization

Install official SyncNet in its own environment; the adapter was written against
commit `907c0b579c2e2d83f0eae1b2ac9e720cde4e5623`:

```bash
git clone https://github.com/joonson/syncnet_python.git /path/to/syncnet_python
git -C /path/to/syncnet_python checkout 907c0b579c2e2d83f0eae1b2ac9e720cde4e5623
cd /path/to/syncnet_python
conda env create -f environment.yml
conda activate syncnet
sh download_model.sh
```

Return to the AutoMV repository and run on **selected singing excerpts**:

```bash
python evaluate/objective/lipsync_score.py \
  --syncnet-root /path/to/syncnet_python --dir /data/singing_excerpts \
  --work-dir evaluate/objective/outputs/syncnet_work \
  --out evaluate/objective/outputs/lse.json
```

Face tracking produces 25 fps face crops; audio is resampled to 16 kHz. If crops
are already prepared, pass `--prepared-crops`. For each face track, LSE-D is the
minimum over temporal shifts of the mean audio–visual feature distance, and
LSE-C is the median shift distance minus that minimum. Outputs retain offsets
and individual track scores. This adapter averages tracks equally within each
input, then inputs equally; use one input per intended evaluation unit.
No detected face is reported as unavailable with a nonzero exit status.
Systems without singing characters have no applicable LSE score.

## Validation and provenance

```bash
python -m unittest discover -s evaluate/objective/tests -v
```

Checks cover archived table reconstruction, the missing CLAP observation, ID
pairing, FVD sampling, SyncNet reduction, and a generated video/audio test for
Beat-only execution and resume behavior. Full pretrained-model evaluation
requires the separate environments, checkpoints and evaluation videos above.

[provenance.json](results/provenance.json) records the local source commit,
original relative paths and hashes. The portable code derives from
`mvmetrics/metric4c_beat.py`, `mvmetrics/eval_batch.py`,
`mvmetrics/metric3c_clap.py`, `mvmetrics/gemini_tagger.py`, and
`vbench_eval/server_artifacts/fvd_compute.py`. The original private server paths
are replaced with command-line inputs. Audio, video and model checkpoints are
provided by the evaluator; this directory includes timing boundaries, captions
and derived scores.

Upstream implementations: [ImageBind](https://github.com/facebookresearch/ImageBind),
[LAION-CLAP](https://github.com/LAION-AI/CLAP),
[cd-fvd](https://github.com/songweige/cdfvd), and
[SyncNet](https://github.com/joonson/syncnet_python). Follow their respective
licenses and cite the corresponding papers when using these metrics.
